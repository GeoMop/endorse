=====================================================================================================
 0. THE BIG PICTURE
=====================================================================================================

 One run answers one question: "if this fractured cube were a homogeneous material, what would its
 6x6 elastic stiffness matrix C be?" The recipe (identical in spirit to your original pipeline):

   (a) Build a cube of rock with fractures in it and mesh it.        -> micro_mesh.py
   (b) Squeeze/shear it in 6 independent ways (KUBC: prescribe       -> kubc.py + template
       displacement u = E_q x on the whole outer boundary).
   (c) For each load, volume-average stress and strain over the      -> postprocess.py
       averaging volume. That gives one column of Sigma and E.
   (d) Solve C = Sigma @ E^-1 and write the report.                  -> upscale_tensor.py

 The one physics upgrade over your original code: TWO concentric cubes. The outer cube
 [0, L_ext]^3 carries the boundary conditions; averaging happens only over the inner cube of edge
 L centered inside it. The shell between them (thickness L/2 per face when L_ext = 2L) is a buffer:
 by Saint-Venant's principle the artificial stress concentrations caused by the rigid boundary
 condition decay across the buffer before they reach the volume you actually measure.
 Setting L_ext_factor: 1.0 in the config removes the buffer and reproduces your original setup.

 Data layout of one finished run (runs/<name>/):
   micro_mesh_healed.msh2            the healed mesh (shared by all six cases)
   pure_normal_E_11/ ... pure_shear_E_12/
       pure_normal_E_11_tmpl.yaml    local template copy
       pure_normal_E_11.yaml         the rendered Flow123d input (placeholders filled in)
       output/mechanics/*.vtu        solver results
   effective_tensor_C_k_kinematic_bc.txt   the report (Sigma, E, C_k, S_k + run metadata)

 5. src/postprocess.py — AVERAGING OVER THE INNER CUBE
=====================================================================================================

 Port of your GeneralComputationClass. Computes the two volume averages (REPORT sec. 3.4.2):

     <sigma> = (1/V) [ sum_bulk sigma_e V_e  +  sum_frac sigma_f A_f delta ]
     <eps>   = (1/V) [ sum_bulk eps_e   V_e  +  sum_frac eps_f   A_f delta ]

 Stress comes straight from the solver output; strain is NOT read from the solver — it is
 reconstructed per element from Hooke's law eps = M : sigma with the analytic isotropic compliance
 of the element's own material. (Same choice as your original code: stress is the primary,
 reliably exported field; fractures use the fracture compliance so their large deformability is
 represented even though geometrically they are thin surfaces.)

 -- build_compliance_matrix_voigt (postprocess.py:31) ---------------------------------------------
 The isotropic 6x6 compliance: 1/E on the normal diagonal (line 37), -nu/E off-diagonal (line 38),
 and 2(1+nu)/E = 1/G on the shear diagonal (line 39). The 2(1+nu)/E form is correct precisely
 BECAUSE the strain vector carries engineering shear gamma: gamma = tau/G.

 -- strain_from_stress (postprocess.py:43) --------------------------------------------------------
 Vectorized Hooke for N elements at once: pack stress tensors to Voigt (lines 46-47), multiply by
 the compliance (line 48), unpack to symmetric 3x3 tensors (lines 49-55). NOTE the /2 at lines
 53-55: the Voigt result is engineering shear gamma, but the TENSOR component is eps = gamma/2.
 The averaging works on tensors (so no convention headaches), and the factor 2 is re-applied only
 at the very end by strain_to_voigt.

 -- parse_stress_field (postprocess.py:59) --------------------------------------------------------
 Defensive reader: Flow123d/pyvista may deliver the stress as (N,3,3), as row-major (N,9), or as
 Voigt (N,6); all three are normalized to (N,3,3). Anything else raises (line 74) instead of
 silently averaging garbage.

 -- average_inner_cube (postprocess.py:87) — the main function ------------------------------------
 1. Read the VTU with pyvista (line 97) and get region_id per element (line 99). This is why the
    template asks Flow123d to output region_id (template line 51) — it is the element's badge
    saying which material/zone it belongs to.

 2. BULK SELECTION (line 107):
        bulk_idx = np.where(rid == region_rock_inner)[0]
    "Is this tetrahedron in the inner cube?" is answered purely BY REGION TAG (rock_inner = 1).
    No geometry test needed: the mesh conforms to the inner-cube boundary (section 2, step 3), so
    the mesher has already decided exactly. Buffer elements (rock_outer = 2) are simply never
    selected — that is the whole "ignore the buffer" mechanism, one line.
    Lines 110-111: element volumes V_e from pyvista's compute_cell_sizes.

 3. FRACTURE SELECTION (lines 116-120) — the barycenter test:
        centers = mesh.cell_centers().points                       (line 118)
        inside  = np.all((centers > lo - tol) & (centers < hi + tol), axis=1)   (line 119)
        frac_in_idx = np.where((rid == region_fractures) & inside)[0]           (line 120)
    Fracture elements all share one region (tag 3) whether they lie in the buffer or in the inner
    cube, so region alone is not enough — the element CENTER is tested against the box [lo, hi]^3
    on all three axes at once (np.all(..., axis=1)). Normally a barycenter criterion is an
    approximation for elements straddling the boundary; here it is EXACT, because conforming
    elements are entirely inside or outside, so their centers are unambiguous. tol (line 104) is
    only round-off protection, ~1e-8.

 4. Fracture weights (lines 126-128): a fracture element is a 2D triangle, so its "volume" is
    area times aperture, V_f = A_f * delta — the thin-plate bookkeeping (REPORT sec. 3.1).

 5. The averages (lines 132-140): concatenate bulk and fracture contributions, then
        sigma_avg = einsum("kij,k->ij", sigma_all, V_all) / V_ref
    i.e. sum over elements k of (tensor_k * weight_k), divided by V_ref = L_inner^3 (line 138).
    Note V_ref is the FULL cube volume, not the sum of element volumes — the tiny volume displaced
    by fracture apertures is intentionally not subtracted (consistent with your original and with
    the thin-fracture limit).

 6. stress_to_voigt / strain_to_voigt (lines 144-151): tensor -> report-ordered 6-vector; the
    strain version multiplies the shear rows by 2 (engineering shear) — the counterpart of the /2
    inside strain_from_stress.

 -- assemble_matrices (upscale_tensor.py:24) ------------------------------------------------------
 Column-stacks the six LoadCaseResults into two 6x6 matrices: column q holds the Voigt vector of
 case q. E = the MEASURED inner-cube-averaged strains, Sigma = the measured average stresses.
 Only measured quantities are used (decision R. Siddall, 9. 7.): with fractures intersecting the
 outer boundary, displacement jumps contribute to the boundary integral and the average strain
 theorem <eps> = E_prescribed no longer holds — the prescribed values would be mathematically
 inconsistent as "results". They remain what they physically are: boundary conditions.

 -- equivalent_tensor (upscale_tensor.py:34) ------------------------------------------------------
 method="exact" (line 42): C = responses @ inv(loads). With loads = E and responses = Sigma this
 is your C_k = Sigma E^-1 (REPORT sec. 2.5.2) — six independent experiments, six unknown columns,
 exact solve. method="ls_symmetric" (line 44) is the reserved slot for the symmetric
 least-squares identification (21 unknowns, >= 36 equations) that J. Brezina wants later — it
 deliberately raises NotImplementedError so nobody can call it by accident.

 -- write_report (upscale_tensor.py:59) -----------------------------------------------------------
 The formatted .txt in the layout of your ORIGINAL GenerateKinematicEffectiveElasticTensor output:
 run metadata header, then the four classic sections — Macroscopic stress matrix Sigma,
 Macroscopic deformation matrix E, Effective Elastic Tensor C_k, Compliance Tensor S_k = inv(C_k)
 — followed by the list of source VTU files so every number is traceable to the simulation that
 produced it. Report file name: effective_tensor_C_k_kinematic_bc.txt (as in your original runs).

 7. src/macro_cube.py — THE CUBIC AVERAGING WINDOW
=====================================================================================================

 NOT used by the single-cube pipeline above. It is the assignment item "MacroCube analogous to
 MacroSphere": in endorse's general homogenisation machinery, every element of a coarse MACRO mesh
 collects micro elements inside an averaging window around its barycenter. MacroSphere uses a
 ball; MacroCube (macro_cube.py:35) uses a cube = a max-norm ball:

     sphere:  np.sum(nc * nc, axis=1) < r * r     (Euclidean norm of node offsets < r)
     cube:    np.max(np.abs(nc), axis=1) < h      (max coordinate offset < h)

 _center_half_edge (line 42): window center = macro-element barycenter; half-edge h = rel_size *
 mean vertex distance from the barycenter (so the window scales with the macro element).
 aabb (line 48): the bounding box used by the framework to pre-filter candidate micro elements.

 interact (line 52) — upgraded past MacroSphere (decision R. Siddall, 9. 7.): it returns the
 VOLUME FRACTION of the micro element inside the window, in [0, 1], instead of MacroSphere's
 all-or-nothing "any node inside" 1/0. Why: on a mesh that does not conform to the window (the
 macro-mesh setting) elements straddle the boundary, and a 0/1 weight miscounts up to one element
 layer of volume. Downstream, Subdomain.weights multiplies this weight by the element volume and
 normalizes, so fraction * V_e = exact overlap volume — precisely the right input. Steps:
   lines 60-61: exact shortcut — all nodes inside the (convex) cube => fraction 1.0;
   lines 62-63: exact shortcut — node bounding box disjoint from the window => 0.0;
   lines 66-68: element cut by the boundary => split it into 8^level EQUAL-VOLUME sub-tets with
     endorse's own refine_barycenters (macro_flow_model.py:239) and return the fraction of
     sub-barycenters inside. Error ~ element_size / 2^level, only for boundary-cut elements;
     level is an attribute (default 2 = 64 sub-tets; verified against Monte-Carlo references).
 On a CONFORMING mesh every element is entirely in or out, so the shortcuts fire and the result
 is exactly 1.0/0.0 — the exact single-cube behaviour costs nothing. (Recorded in PLAN.md:
 MacroSphere still uses the 0/1 indicator and stores a rel_radius its code never reads; whether
 it should get the same volume-fraction upgrade upstream is a question for J. Brezina.)

 In the future macro-mesh phase, these windows are what replaces the conforming inner cube — in
 the current single-cube app the conforming mesh makes all of it degenerate to exact V_e / V_inner
 weights, which is why MacroCube can sit unused without loss.
